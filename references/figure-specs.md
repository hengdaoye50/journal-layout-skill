# 图件规范（figure-specs）

本文件是 `journal-layout-skill` 图件子系统的作图与嵌入约定。适用于正文中的机制示意图、
框架图（不含照片、统计图）。所有路径相对 skill 根目录：

```
journal-layout-skill/
├─ scripts/figlib.py            # 绘制原语库（Pillow 光栅 + 同步 SVG）
├─ scripts/embed_figure.py      # 把 PNG 嵌进 docx 内嵌图（只改图字节 + cx/cy）
├─ examples/figure1_demo.py     # 两机制并列示例（图1 简化版）
└─ examples/out/                # 示例产物 PNG / SVG / 黑白 SVG
```

## 1 画布与尺寸

- **逻辑画布 1200×770 像素**（4:2.57，接近通栏图），`scale=3` 超采样，`dpi=600`。
  输出 PNG 为 **3600×2310 px**；3600px / 600dpi = 6 英寸 = 152.4mm，正好落在通栏宽内。
- **通栏宽按 160mm 制作**。四刊版心略有差异（政治学研究、中国行政管理约 15.5–16cm；
  管理世界、公共管理学报略窄），因此：
  - 作图与 SVG 统一用 160mm（`Canvas(width_mm=160)`）；
  - 嵌入 docx 时用各刊已校准的 `cx`（例如 12.65–14.80cm），**等比缩小，不改 PNG**；
  - 只有需要铺满版心时才用 `--width-cm 16`（或按刊给 15.5/15.2 等），高度由 PNG
    纵横比自动重算，绝不拉伸。
- 分辨率核算：3600px ÷ 160mm = **571dpi**，缩到 138mm 仍有 662dpi，远高于印刷 300dpi
  下限。不要为了“更清晰”把画布加大到 2400 逻辑像素——字号会同步变大，排版反而失控。
- 字号换算：1 逻辑像素 = 160/1200 mm = 0.1333mm = **0.378pt**。
  - 图内正文：21–22px ≈ 7.9–8.3pt；
  - 节点标题 / 机制小标题：22–24px ≈ 8.3–9.1pt；
  - 机制名（大标题）：26–29px ≈ 9.8–11.0pt；
  - 图例：19–20px ≈ 7.2–7.6pt；
  - **图内最小 21px（≈7.9pt），7.5pt 是下限（≈20px），不得更小**。
- 图片在 docx 中**不得拉伸**：`cx/cy` 必须与 PNG 纵横比一致。`embed_figure.py`
  默认保留现有宽度、按新图纵横比重算高度，并对纵横比变化打印提示。

## 2 灰度、线宽与黑白化

只用白与灰，不引入色相。按“主框 / 次框 / 辅助”三档线：

| 层级 | 用途 | 颜色 | 线宽（逻辑 px） |
|---|---|---|---|
| 主框 | 机制外框、结果框、主箭头 | `#333333`–`#555555` | 1.1–1.3 |
| 次框 | 内部节点、行框、支撑箭头 | `#7b7b7b`–`#aaaaaa` | 0.8–1.0 |
| 辅助 | 背景条、图例外框、分隔线 | `#b0b0b0`–`#c0c0c0` | 0.6–0.8 |

- 填充只用 `#ffffff` / `#f5f5f5` / `#f1f1f1` / `#ededed`；文字用 `#181818`–`#333333`。
- 箭头默认 9px 逻辑长度（`arrow_size=9`），虚线默认 `(6,5)`（与参考脚本一致）。
- **纯黑白投稿件必须黑白化**：`figlib.black_white(src.svg, out_bw.svg)` 按亮度压成四档
  `245 / 180 / 85 / 25`（规则与 `06_处理脚本与临时数据/render_figures.cjs` 相同：
  >210 → 245，>140 → 180，>90 → 85，其余 → 25）。交付前检查 `*_bw.svg` 中无彩色值。

## 3 字体

- 图内字体两套：**正文宋体（SimSun）、标题黑体（SimHei）**，不混入第三套。
- `figlib` 自动探测 `simhei.ttf` / `simsun.ttc` / `msyh.ttc`，可用环境变量
  `FIGLIB_FONT_REGULAR` / `FIGLIB_FONT_BOLD` 指定路径；探测不到时回退并告警。
  **验收前先看 stderr / `font_warnings()`**：出现回退说明中文可能是方框。
- SVG 依赖本机字体：换机器打开前确认装有宋体/黑体；投稿 PDF 建议转曲或嵌入字体。
- 图内字号不得低于 7.5pt（≈21px @1200 逻辑宽）。缩小整图时（如 160mm → 12.65cm），
  字号随之等比变小，必须重算：12.65cm 通栏下 21px 只剩 ≈6.3pt，**不能直接缩**，
  应改 `width_mm`/布局重画或保持 160mm 只让 docx 裁边距。

## 4 图例与语义约定

- **实线 = 机制过程 / 因果方向**；**虚线 = 条件支撑 / 前提**。不得混用。
- 虚线箭头指向**机制区域整体**（如“基础条件”指向“机制 B”整块），不要指向任意
  子环节，否则读图会把并列条件误读成时序阶段。
- 底部括号汇聚表示**共同作用**，不表示任一机制单独充分；图中不宣称充分因果。
- 图例放在图内底部，一条示例线 + 说明文字（`legend_line()`），不放在题注里。

## 5 题注

- 题注在**图下方居中**，格式“图1 标题”，中文宋体，字号按刊（一般 5 号/小 5）。
- 题注不进图片本身；PNG/SVG 内不放“图1”字样。
- 若有数据来源/说明，另起一行、字号小于题注，仍居中。
- docx 中图段与题注段间距保持固定；`embed_figure.py` 只改 drawing 容器，不重排版式。

## 6 图与正文论证一一对应核对表（强制）

作图前先填这张表，**每个箭头/连线都必须有正文依据**；填不出的关系就删掉，不能先画图
后找依据。

| 图中关系 | 正文依据 | 表达边界 |
|---|---|---|
| （画出的每条线/每个框） | （第几节第几小节、哪段论述） | （该关系不能推出什么、不能夸大什么） |

纪律：

1. 图只承担正文已论证的关系，**不得用图证明充分因果**；
2. 视觉对称 ≠ 理论对称：左右等宽要说明是否等权（示例图两机制等宽，但因果角色不同）；
3. 过程、条件、结果三种语义分开，同一层级才比较；
4. 逐条核对表随图归档（例：`04_论文图件/图1_机制重构/设计与正文依据.md`）。

示例核对表（对应 `examples/figure1_demo.py` 的图；复制这张表，把「正文依据」换成自己
正文的节次，填不出的关系就删掉，不要先画图后找依据）：

| 图中关系 | 正文依据 | 表达边界 |
|---|---|---|
| 背景因素一 → 背景因素二 → 背景因素三 | 第 X 节（一） | 只作问题背景，不画成自动触发后续机制 |
| 机制 A：环节一 → 环节二 → 环节三 | 第 X 节（二） | 只画正文已论证的链条，不补画未论证环节 |
| 机制 B：环节一 → 环节二 → 环节三 | 第 X 节（三） | 同上；两机制并列，不意味着等权 |
| 条件一 / 条件二 / 条件三 → 机制 B（整块） | 第 X 节（四） | 虚线连整块机制，不拆成三个时序阶段 |
| 机制 A、机制 B → 共同结果 | 第 X 节（五） | 不是充分因果条件 |

## 7 双产物纪律与工作流

唯一真源是**布局脚本 `.py`**；SVG 与 PNG 都是它的产物，**禁止手改 SVG/PNG**。

1. 新建图：复制 `examples/figure1_demo.py`，改 `draw()` 里的布局；
2. 生成：`python examples/figure1_demo.py` → `examples/out/*.png` + `*.svg`；
3. 需要黑白投稿版：脚本内调用 `black_white(svg, out_bw_svg)`；
4. 先只读检查嵌入目标：
   ```powershell
   python scripts/embed_figure.py --docx <docx> --image <png> --dry-run
   ```
   确认“将替换第几张 / media / 当前尺寸 → 新尺寸”；
5. 正式嵌入（原地替换前先看是否需要备份）：
   ```powershell
   python scripts/embed_figure.py --docx <docx> --image <png> --index 1 --backup
   ```
   或输出到新文件：`--out new.docx`（原文件不动，便于比对）；
   `--occurrence 0` 与 `--index 1` 等价，保留给旧脚本；
6. 需要改宽度时显式给 `--width-cm 16`（或按刊 15.5/15.2），高度自动按纵横比重算。

`embed_figure.py` 的保护性断言（每次运行、含 `--dry-run`，失败即中止且不写坏文件）：

- 替换前后 `word/document.xml` 的 `//w:t` 文本序列**完全一致**；
- 包内部件只有 `word/document.xml` 与目标 `word/media/*.png` 变化；
- 新包能重新打开，media 字节、`wp:extent` 的 `cx/cy` 与预期一致；
- 先写 `.tmp`，校验通过后才 `replace`；`--dry-run` 全程不落盘。

- [ ] `python examples/figure1_demo.py` 跑通；PNG 宽度 ≥1200px（实际 3600px）、
      `dpi=(600,600)`；
- [ ] SVG 头 `width="160mm"`、`viewBox="0 0 1200 770"`，可被 XML 解析；
- [ ] 黑白 SVG 中无彩色值；
- [ ] `import figlib` 无副作用（不建画布、不读字体、不写文件、无告警）；
- [ ] `embed_figure.py --dry-run` 报告正确目标与尺寸，且目标 docx 的 SHA256 不变、
      无 `.tmp` 残留；
- [ ] 正式嵌入后：文本 `//w:t` 不变、仅两个部件变化、cx/cy 与 PNG 纵横比一致；
- [ ] 第 6 节核对表已填，图内每条关系都有正文依据。

## 9 常见坑

1. **SVG 与 Pillow 文本基线不完全一致**：Pillow 的 `anchor='mm'` 按字形实际 bbox 中心
   对齐，SVG `dominant-baseline="central"` 按字体 em 中心，通常差 1–2 逻辑像素；
   同一布局以 **PNG 为准**。混用 `mt`/`mb` 锚点时误差更明显，一张图只用一种锚点。
2. **虚线相位**：Pillow 逐段画虚线，SVG 用 `stroke-dasharray` 连续相位，拐角处相位
   不同，视觉上 1px 级差异；关键图以 PNG 为准。
3. **字体回退**：无中文字体的机器上会告警并回退，中文变成方框；批量生成前先看
   `font_warnings()`，或设置 `FIGLIB_FONT_*` 环境变量。
4. **600dpi 只是 PNG 元数据**：打印尺寸由 docx 的 `cx/cy` 决定，两者要匹配；
   改了 PNG 不重嵌 docx，版面不会自动更新。另外 PNG 的 pHYs 只能存整数像素/米，
   600dpi 写入 23622 px/m，读回来是 599.9988，**用 round() 判断为 600** 即可。
5. **同一 media 被多图共用**：替换会一起变；`embed_figure.py` 会打印警告。
6. **只支持 PNG**：按 IHDR 读尺寸，jpg/webp 会被拒绝；docx 里 rels 指向的部件必须是
   `word/media/*.png`。
7. **嵌入范围**：只处理 `word/document.xml` 里的 `wp:inline` / `wp:anchor`；
   页眉页脚、脚注、文本框里的图不在范围内。
8. **不要原地反复实验**：先用 `--out` 写新文件比对，确认后再原地替换；保留旧版 docx。
